# wellbegun 0.6.0 — Lean execution and bounded context

Small tasks now complete directly, with implementer reuse inside verified
boundaries. Explicit independent gates block consumers before new shared
foundations spread. Both Claude Code and Codex manifests use version `0.6.0`.

- Select current contracts, active decisions and relevant registry entries instead
  of loading execution history. Default runtime output ceiling: 12KB, with explicit
  expansion for required sections.
- New cycles use schema 2 state with checkpoint recovery, valid check reuse,
  derived run/HANDOFF documents and archive. Existing legacy cycles retain their format.
- Create only needed registries/foundations. Triage small follow-up work before
  entering a new planning cycle.
- Preserve unresolved gates, pending decisions and round caps. Same-file changes
  trigger necessary revalidation while preserving implementation and resume progress.

Validation: 88 runtime/lifecycle tests, independent G1 round 7 ACCEPT and final
review round 2 ACCEPT. The tested runtime and test inputs are unchanged for this
release; prior valid results are reused. Installed CLI lifecycle smoke also passed.

Controlled step observations showed lower document input and fewer model roles.
These single-sample observations do not guarantee general speed, token or monetary
savings. Seven broader Flutter failures on baseline-identical dogfood code remain
reported separately; the project-wide suite is not claimed green. Synthetic smoke
gate identities test protocol, not independent agent judgment.

Python 3.9+ is required for the standard-library runtime. Without Python, explicit
manual/legacy operation is available, without automated schema 2 guarantees.
Git/hooks are optional; fresh verification requires an independent context.

Install from marketplace `ardenspace/wellbegun`, plugin `wellbegun@wellbegun`.
For Codex, `codex plugin add wellbegun@wellbegun` installs from the configured
marketplace. Start a new thread to load the updated skills. A marketplace configured
to a development folder continues using that folder until its source is changed.

See `docs/2026-09-12-lean-execution-validation.md` for measured results and limitations.
