# wellbegun 0.8.1 — Forwards that actually arrive

Fixes from a review of 0.8.0 against kongkong's real `deferred.md`. The point
of 0.8.0's forwarding was that a finding passed to a later record reaches it;
two gaps could still lose or bury those findings.

- A `→` counts as a forward only when the name after it is a record in the
  plan, and the last such arrow on the line wins. Prose arrows such as
  `src→worker`, `resolves → complete` or `KRW → 10/30/50` no longer appear as
  open forwards.
- Forward lists are never trimmed before other notes. The notes budget is
  6000 bytes, trimmed in the order review items, screenshot reviews, rechecks,
  open forwards, forwarded; if a forward list must still be cut, a hint tells
  the reader to read the `→` lines in `deferred.md` and `rule-candidates.md`
  directly. Explicit section fetches no longer carry notes.
- A changed foundation leaves `notes.review_items` once a later fresh record
  accepts it with a verifier; it returns if its files change again. Checks-only
  rechecks do not count as that review.
- wellrun says what a gate's `target` must hold: the shared contract files its
  producers built. The changed-foundation warning watches exactly those files.
