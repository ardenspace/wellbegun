# wellbegun 0.8.2 — Registry upkeep without reopening

Fixes from kongkong's first cycle on 0.8.1 (2026-11-08). The implementer kept a
registry entry out of date on purpose, because listing one new shared file in it
would have reopened the gate and every consumer.

- A registry entry's `location` is no longer part of a record's input identity.
  Listing or moving a file there keeps verified records verified; the change
  reaches the next fresh point as `notes.review_items`
  (`{record,registry,location}`) until a fresh ACCEPT. Changes to `contract`,
  `constraints` or `decisions` still reopen. Digests stored before 0.8.2 are
  still accepted.
- Errors say what to do next. Drift errors name the changed `files` or
  `records` and carry a `next` recovery call; a missing verification command
  lists `missing` and `given`, since commands must match the contract text
  exactly.
- wellrun states that, without a new L/XL decision, a pending question or a
  runtime stop, the run goes straight on to the next record.
