# wellbegun 0.8.3 — Registry upkeep for records from 0.8.1

kongkong's review of 0.8.2 against its real state found that 0.8.2's main fix
did not reach records verified under 0.8.1. 0.8.2's note "Digests stored before
0.8.2 are still accepted" held only while the registry was unchanged.

- Records started before 0.8.2 stored only a digest that includes registry
  locations, so a location edit made them drift. The first helper call
  (context, transition or render) that still finds that digest matching now
  stores a location-free `input_identity` beside it; later location edits keep
  those records verified. After upgrading, run any helper command once before
  editing a registry location. An edit made before that call cannot be told
  apart from a contract change, and still reopens.
- The completed-cycle drift error now carries the `next` recovery call. The
  recovery hint no longer assumes the record was checking: reconcile, re-read,
  then set each stopped record to its saved `resume_status`.
- A fresh record's own registry locations are updated on its ACCEPT, so the
  next fresh point does not get a review item its verifier already saw.
