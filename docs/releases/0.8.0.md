# wellbegun 0.8.0 — Lean wellrun verification

Fresh review moves to a few planned points after larger work, and code changes
stop invalidating verified records
([design](../2026-11-05-lean-wellrun-verification-design.md)). In the kongkong
comparison, review after small steps found little, while 78 invalidations from
15 code changes drove the cost; review after larger work found real defects but
some were deferred and lost. Wall-clock time, not tokens, was the complaint.

- Fresh review sits only at a gate after each new shared foundation, one gate
  where money and auth flows first connect, and whole-run. Steps and phases are
  basic. An L/XL step outside these points carries a one-line "fresh not
  needed" reason in Run preview, which now shows fresh points, expected agents
  and the recheck policy.
- Fresh records may set `perspectives` (`goal`, `abuse`, `money`). Gate
  verifiers cover them in one context; whole-run runs one verifier per
  perspective in parallel and counts them as one round. Reverification reruns
  only rejecting perspectives. Finding IDs carry the perspective prefix.
- Verified records are reopened only by a change to their contract or selected
  decisions/registry entries, never by later code, check-input or runtime
  changes. A verified gate whose files change later is listed in the next fresh
  point's `notes.review_items`.
- After a contract change, a previously accepted fresh record may recheck with
  checks only and a recorded `recheck_reason`; whole-run sees every such case.
- Lines in `deferred.md` and `rule-candidates.md` ending with
  `→ <record ID>` reach that record's packet as `notes.forwarded`; whole-run
  lists every open forward. Packet `notes` carry no receipts and never drift.
- Outside-contract findings touching abuse, money or a `begin.md` promise are
  fixed now when S/M and in scope, and forwarded to the next fresh point; only
  promise changes or L/XL choices go to the user, as one question per review.
- Phase integration is basic: the implementer runs e2e and reviews screenshots.
  The test-count rule applies to basic steps and phases too.

In-progress schema 2 cycles get the relaxed drift rule immediately. Existing
approved plans stay valid: `perspectives` is optional, fresh steps and phases
remain legal, and a whole-run round already started or accepted with a single
verifier finishes or stays valid on that path. The schema number is unchanged.
