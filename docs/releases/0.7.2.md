# wellbegun 0.7.2 — Adopting existing projects

wellbegun can now start in a project that was built without it. Plans and state
files behave as before; the runtime is unchanged.

- wellnext Step 0 (adopt): when `.wellbegun/` is missing but the project already
  has code or another tool's planning documents, wellnext drafts `begin.md` from
  those sources (each item with its source, unsettled items marked `unconfirmed`),
  carries only the active L/XL decisions that constrain current work, and asks
  the user for one confirmation instead of running the seven-bundle conversation.
  It then triages the new work as usual; nothing is archived.
- `begin.md` frontmatter gains `adopted_from` and the `entry` values `pending`
  (adoption interrupted) and `none` (adopted, no cycle open).
- wellbegin routes an existing project without `begin.md` to wellnext unless the
  user asks to reshape the product from scratch. wellbegin and wellspec route
  `entry: pending | none` to wellnext.
