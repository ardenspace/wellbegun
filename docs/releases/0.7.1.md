# wellbegun 0.7.1 — Check contract follow-ups

Clarifications to the 0.7.0 check contract. Plans and state files behave as before.

- `round_limit` applies to fresh step and gate contracts only; basic, phase and
  whole-run contracts omit it. The check command still goes in every contract's
  `verification`.
- `references/check-contract.md` says where each class's knowledge lives: lint in
  the rule message, test in the test name and assertion message, area-only review
  in that area's CLAUDE.md or AGENTS.md, and only a one-line root pointer for
  what almost every task needs.
- Rule messages are written as corrections: what to use instead and where it lives.
- Registries point to an existing code-derived list (an `index.ts` export list,
  a Storybook) instead of copying its rows.
- wellnext and wellrun drop leftover "enforcement" wording; wellnext states that
  `rule-candidates.md` and the previous audit move only when they exist.
- New test: raising `round_limit` on an existing scope keeps its limit
  (99 runtime/lifecycle tests).
